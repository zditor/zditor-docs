## ドラッグ＆ドロップ

### 5 種類のドラッグ＆ドロップ

Zditor では、ドラッグ＆ドロップをいくつかの方法で使えます。

#### 1. ファイルツリー内でのドラッグ

左側のファイルツリーにあるファイルやフォルダーは、ツリー内でドラッグして、ワークスペース内での場所を変えられます。

次のような場合に便利です。

- フォルダー構成を整理し直す
- ファイルを別のフォルダーに移動する
- ワークスペースの構成をすっきりさせる

#### 2. ファイルツリーから Markdown ドキュメントへのドラッグ

左側のファイルツリーにあるファイルを、Markdown ドキュメントに直接ドラッグできます。

ドロップしたファイルは、ワークスペース内の元の場所にあるファイルへリンクする**添付ファイルノード**として挿入されます。Zditor はコピーを作りません。

代わりに画像、動画、オーディオプレーヤー、キャンバスとして表示するには、次のようにします。

1. 添付ファイルをクリックし、**More** メニューを開いて **Convert to Link** を選びます。
2. 作成されたリンクをクリックし、リンクツールバーで該当するボタン（**Convert to image**、**Convert to video**、**Convert to audio**、**Convert to canvas**）を使います。ファイルの種類に合うボタンだけが表示されます。

キャンバスファイル（`.excalidraw`）の場合は、添付ファイルの **More** メニューから直接 **Convert to Canvas** を選ぶこともできます。

先に挿入しておき、最終的な見せ方を後で決めたいときに便利です。

#### 3. 外部のファイルを Markdown ドキュメントへドラッグ

システムのファイルマネージャーから、Markdown ドキュメントにファイルを直接ドラッグできます。

Zditor はファイルの種類に応じて次のように挿入します。

- 画像ファイル → 画像ノード
- 動画ファイル → 動画ノード
- 音声ファイル → 音声ノード
- キャンバスファイル（`.excalidraw`）→ キャンバスノード
- その他のファイル → 添付ファイルノード

ドロップした各ファイルのコピーは、**Settings → Integrations → Image hosting & uploads** で設定した場所に保存されます。ローカルの素材をノートやドキュメントに取り込む最も手早い方法です。

#### 4. Markdown ドキュメント間でのノードのドラッグ

左右の分割ペインの間など、異なる Markdown ドキュメントの間でノードをドラッグできます。

ドキュメント間での既定の動作は**コピー**です。ドロップ先のドキュメントにコピーが入り、元のノードはドラッグ元のドキュメントに残ります。

次のような場合に便利です。

- 下書きの内容を正式なドキュメントに移す
- 分割ペインの間でブロックを再利用する
- 複数のノートにまたがって内容を整理し直す

#### 5. 同じドキュメント内でのドラッグ

1 つのドキュメントの中では、ブロック単位のコンテンツを、カット＆ペーストせずにドラッグで別の位置へ移動できます。

同じドキュメント内での既定の動作は**移動**です。

次のような場合に便利です。

- 段落を並べ替える
- セクションの構成を変える
- テキスト、画像、コードブロックをより適切な位置に移す

### エディター内のドラッグハンドル

編集中にブロックにポインターを合わせると、左の余白にドラッグハンドルが表示されます。ハンドルには、つまみの横にブロックの種類（見出しなら `H1`〜`H6`）が表示されます。これをドラッグすると、ブロック全体が移動します。

このハンドルは、次のようなすべての最上位ブロックにあります。

- 段落
- 見出し
- リスト
- 引用
- 画像
- 動画
- コードブロック
- 添付ファイル
- コールアウト
- 表
- ディスプレイ数式

リストは全体がまとめて移動します。リスト項目を 1 つだけ移動するには、`Alt-ArrowUp` と `Alt-ArrowDown` を使います。

<Warning>
  **ドラッグ＆ドロップについてのフィードバック**

  正しくドラッグできない種類のノードを見つけた場合、たとえば次のような場合は、

  - ドラッグできない
  - 間違った位置にドロップされる
  - ドロップした後に内容がおかしくなる

  不具合として報告してください。足りない部分を引き続き修正していきます。
</Warning>

### ドラッグを開始できる場所

ドラッグは次の 2 か所から開始できます。

- **左の余白**：ポインターを合わせると表示されるハンドル。すべての最上位ブロックで使えます
- **ツールバー**：画像、動画、音声ファイル、添付ファイル、キャンバス、埋め込み、コードブロック、表、HTML ブロック、数式を選択したときのツールバーにある **Drag** ボタン

<Tip>
  ドラッグ＆ドロップの真価は、構造の編集にあります。長いノートや下書き、アウトラインを組み替えるときは、カット＆ペーストよりずっと速く作業できます。
</Tip>

## キーボードショートカット

キーボードショートカットは、Zditor での編集を速くする最も効果的な方法の 1 つです。

よく使う場面は次のとおりです。

- ドキュメントの保存
- 内容の検索
- 見出しレベルの設定
- 太字、斜体、ハイライト、インラインコードの切り替え
- リスト、引用、表、コードブロック、数式の作成

### まず覚えたいショートカット

| ショートカット | 操作 |
| --- | --- |
| `Mod-K` | 検索を開く |
| `Mod-S` | 現在のドキュメントを保存 |
| `Mod-F` | 現在のドキュメント内を検索 |
| `Mod-/` | リッチテキストとソース表示の切り替え |
| `Mod-B` | 太字の切り替え |
| `Mod-I` | 斜体の切り替え |
| `Mod-H` | ハイライトの切り替え |
| `Mod-Shift-C` | インラインコードの切り替え |
| `Mod-1`〜`Mod-6` | 見出しレベルを設定 |
| `Mod-Shift-8` | 箇条書きリストの切り替え |
| `Mod-Shift-7` | 番号付きリストの切り替え |
| `Mod-Shift-9` | チェックボックスリストの切り替え |
| `Mod-Shift-\` | コードブロックの切り替え |
| `Mod-T` | 表を作成 |

<Warning>
  `Mod` は次のキーを表します。
  <ul>
    <li><strong>macOS</strong>：`Command`</li>
    <li><strong>Windows / Linux</strong>：`Ctrl`</li>
  </ul>
</Warning>

### ショートカットが特に役立つ場面

ショートカットは、次のような場合に特に便利です。

- 使いたい書式や構造がすでに決まっている
- マウスに手を伸ばして作業の流れを止めたくない
- 同じ操作を何度も繰り返す

ショートカットの全一覧と、**Settings → Personal → Keyboard shortcuts** でキー割り当てを変更する方法については、[キーボードショートカット](/ja/keyboard-shortcuts)を参照してください。

## トリガーメニュー

トリガーメニューを使うと、構造化された操作をキーボードから最もすばやく呼び出せます。

### `/` コマンドメニュー

Markdown ドキュメントで、行頭またはスペースの後に `/` を入力すると、コマンドメニューが開きます。続けて入力すると項目が絞り込まれ、すべてのグループの中が検索されます。矢印キーと `Enter` で項目を選びます。

メニューには次の項目があります。

- **Heading 1**〜**Heading 3** と **Heading 4-6**
- **List**：チェックリスト、箇条書きリスト、番号付きリスト
- **Media**：画像、動画、音声、キャンバス、添付ファイル（いずれもファイル選択ダイアログで選びます）
- **MetaInfo**：ドキュメント先頭の Frontmatter ブロック
- **Code Block**：表、HTML、引用、コードブロック、ディスプレイ数式、区切り線、改ページ、Mermaid 図
- **Info**：情報、メモ、警告、ヒント、エラーの各コールアウト
- **Templates**：Frontmatter に `template: true` があるドキュメントがある場合に表示されます。テンプレートを選ぶと、現在のドキュメントの内容がそのテンプレートに置き換わります。

これにより、次のことができます。

- 同じ入力を繰り返さずに済む
- 使えるコマンドをすぐに見つけられる
- より構造化された手順で作業できる

エージェントのメッセージ入力欄では、`/` を入力すると会話用のコマンド（`/share`、`/export`、`/goal`、`/compact`、`/side`）が一覧表示されます。入力欄では、`@` でワークスペースのファイルを指定し、`$` でスキルを選びます。[エージェントガイド](/ja/agent-guide)を参照してください。

### エディターのその他のトリガーメニュー

エディターには、`/` のほかにもよく使うトリガーメニューがあります。

- `@`：ワークスペース内の Markdown ファイルや PDF ファイルへのリンクを挿入します。ハイライトのある PDF では、ハイライトを選んで PDF カードとして挿入することもできます。
- `#`：SuperTag の項目を挿入または作成します。
- `:`：絵文字ピッカーを開きます。続けて入力すると、名前で絵文字を絞り込めます。

各メニューは、**Settings → Editor → Markdown Editor** の **Command menu (/)**、**Link menu (@)**、**Object menu (#)**、**Emoji menu (:)** でオフにできます。

<Tip>
  同じエディター操作を頻繁に繰り返すなら、毎回同じ構文を入力し直すより、トリガーメニューを使うほうがたいてい速く確実です。
</Tip>

## ツールバー

Zditor の書式ツールバーは、1 つに固定されているわけではありません。選択した内容に応じて、それに合ったツールバーを表示します。

### 選択ツールバー

テキストやノードを選択すると、エディターはそれに合ったツールバーを表示します。たとえば次のようなものがあります。

- テキスト書式ツールバー
- リンクツールバー
- 画像、動画、音声のツールバー
- 添付ファイルツールバー
- キャンバスツールバー
- 埋め込みツールバー
- コードブロックと HTML ブロックのツールバー
- 数式ツールバー
- 表ツールバー
- コールアウトツールバー
- 脚注ツールバー
- 注釈マークと修正マークのツールバー
- SuperTag ツールバー
- PDF カードツールバー

そのため、構文をすべて覚えておく必要はほとんどありません。よくある使い方は次のとおりです。

1. まず内容を選択する
2. ツールバーで操作を適用したり調整したりする

これらのツールバーを非表示にするには、**Settings → Editor → Markdown Editor** で **Selection toolbar** をオフにします。

### ツールバーの動作

<AccordionGroup>
  <Accordion title="選択したオブジェクトに応じて変化" icon="arrows-rotate" defaultOpen>
    オブジェクトごとに異なるツールバーが表示されます。テキストでは書式ツール、画像では画像ツール、PDF カードでは PDF カード専用のツールバーが表示されます。
  </Accordion>

  <Accordion title="2 つ目のフローティングパネル" icon="layer-group">
    ツールバーのボタンによっては、より細かいオプションや対象を選ぶための 2 つ目のフローティングパネルが開きます。
  </Accordion>

  <Accordion title="その場で編集" icon="pen-to-square">
    ツールバーは選択した内容の近くに表示されるので、編集箇所から目を離さずに作業できます。
  </Accordion>

  <Accordion title="選択範囲をエージェントに渡す" icon="sparkles">
    多くのツールバーには **ASK AI** ボタンがあり、選択範囲を添付した状態でドキュメントの横にエージェントを開きます。**Settings → AI → AI Toolbar Prompts** で追加したプロンプトは、ツールバーに追加のボタンとして表示されます。
  </Accordion>
</AccordionGroup>

### ツールバーが特に役立つ場面

ツールバーは、次のような場合に特に便利です。

- 編集したい内容は決まっているが、構文は覚えたくない
- 決める前に、どんな操作ができるかを確認したい
- 画像、添付ファイル、PDF カード、SuperTag などの視覚的なノードを扱う

## おすすめの習得順序

Zditor を使い始めたばかりなら、次の順序で覚えると効率的です。

1. 構造の編集のためにドラッグ＆ドロップを覚える
2. よく使うキーボードショートカットをいくつか覚える
3. `/`、`@`、`#`、`:` のトリガーメニューを使い始める
4. 実際に書きながら、オブジェクトごとのツールバーに慣れる
