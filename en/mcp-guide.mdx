MCP, the Model Context Protocol, is an open standard for connecting AI agents to tools and data. When you add an MCP server to Zditor, the agent can use its tools in every Agent conversation, alongside its built-in tools.

<Warning>
  Connect only servers you trust. A **Stdio** server is a program that runs on your computer with your access rights, and every server receives what the agent sends to its tools.
</Warning>

## When you need MCP

The agent already works with your files, PDFs and canvases, runs commands and operates Zditor itself (see the [Agent Guide](/en/agent-guide)). Add an MCP server when a task needs something beyond that, such as an issue tracker, a database, a knowledge base or another app's data.

## Add a server

<Steps>
  <Step title="Open the MCP settings">
    Open **Settings → AI → MCP Servers** and click **Add server**.
  </Step>

  <Step title="Name the server">
    Enter a **Server name**. It identifies the server in lists, status updates and tool calls, and it must be unique. The name `zditor` is reserved.
  </Step>

  <Step title="Choose how to connect">
    Under **Transport**, choose **Stdio** to have Zditor start the server as a program on your computer, or **HTTP** or **SSE** to connect to a server at a web address. Then fill in the fields for that transport, described in the table below.
  </Step>

  <Step title="Test and save">
    Click **Test connection**. When it works, Zditor reports how many tools it found. Then click **Save**.
  </Step>
</Steps>

| Field | Transport | What to enter |
| :--- | :--- | :--- |
| **Command** | Stdio | The program that starts the server, such as `npx` or the full path of an executable. Required. |
| **Arguments** | Stdio | Command-line arguments for the program. Put quotes around a value that contains spaces. |
| **Environment variables** | Stdio | Names and values set for the server's process, such as an API token. |
| **Endpoint URL** | HTTP, SSE | The server's full `http://` or `https://` address. Required. |
| **Request headers** | HTTP, SSE | Names and values sent with every request, commonly `Authorization` with a bearer token. |

<Tip>
  You can also ask the agent to add, change or remove an MCP server for you. Changing settings needs your approval in **Always ask** mode.
</Tip>

## Turn servers on and off

Each server in the list has a switch. When a server is off, it shows as **Disabled**, and conversations don't connect to it or load its tools. The server's form has the same switch under **Status**.

Changes apply from the agent's next turn, also in conversations that are already open. To change a server, click **Edit**. **Discard** drops unsaved changes, and **Delete** followed by **Confirm delete** removes the server.

## Use MCP tools in a conversation

You don't choose servers for each conversation: every enabled server is available in every Agent conversation. The agent looks up a server's tools when a task needs them, and naming the server or the tool in your request helps it choose.

- In **Always ask** mode, each MCP tool call needs your approval. Reading the resources a server offers doesn't.
- A server can ask you for information while it works. The conversation then shows a form from that server: fill it in and click **Submit**, or click **Decline**. If the server asks you to visit a web page, **Open and continue** opens it.

## On iPhone and iPad

Zditor can't start programs on iPhone and iPad, so use **HTTP** or **SSE** servers there.

## The former built-in Zditor MCP service

<Note>
  Earlier versions of Zditor came with a built-in MCP service that offered tools such as `open_file`, `list_supertag_classes`, `list_agent_sessions` and `generate_image`. It's no longer part of Zditor. The agent has its own tools for working with Zditor instead: it can read your workspace and open tabs, open files, switch and close tabs, change settings, and work with PDFs and canvases. The SuperTag, session-history and image tools have no built-in replacement. A server named `zditor` left from an earlier setup is removed automatically, and the name is reserved.
</Note>

## Permissions and safety

- Enable only the servers a task needs, and turn off the ones you aren't using.
- Keep **Always ask** for servers whose tools can change things.
- Put tokens and keys in **Environment variables** or **Request headers**, not in your messages. The form hides their values until you show them.
- Server settings, including those values, are saved on this device. If you back up **Connections and credentials** in **Settings → Personal → Sync**, they're included in the encrypted backup.
- Prefer tokens with a limited scope, and rotate them regularly.

## FAQ

<AccordionGroup>
  <Accordion title="Test connection fails for a Stdio server" icon="terminal">
    Zditor doesn't show the server's own error output, so run the same command in a terminal to see what goes wrong. If the program isn't found, enter its full path in **Command**. Apps opened from the Dock or Finder may not see the same `PATH` as your terminal: if the server needs other programs, such as Node.js for `npx`, add a `PATH` environment variable set to the output of `echo $PATH` in your terminal.
  </Accordion>

  <Accordion title="Test connection fails for an HTTP or SSE server" icon="globe">
    Check the **Endpoint URL** and any **Request headers**, such as an expired token. Zditor sends every request to the endpoint URL as an HTTP POST and accepts JSON or event-stream replies, so a server that only supports the older SSE transport, with a separate address for its event stream, may not connect. Use the server's streamable HTTP address if it has one.
  </Accordion>

  <Accordion title="The server is connected but the agent doesn't use it" icon="question">
    Check that its switch is on and that **Test connection** finds tools. Then name the server or the tool in your request: the agent looks up MCP tools when it decides a task needs them.
  </Accordion>

  <Accordion title="Replies got slower after adding servers" icon="hourglass-half">
    Zditor starts every enabled server before the agent's first turn in a conversation, and again after you change the server list, so a slow server delays the reply. Turn off the servers you don't need.
  </Accordion>
</AccordionGroup>
