SuperTag lets Zditor treat Markdown files as structured records and render references to those records as tag-like chips inside documents.

## Overview

<CardGroup cols={2}>
  <Card title="Structured records" icon="database">
    Store reusable metadata in frontmatter while keeping the body as normal Markdown.
  </Card>

  <Card title="Shared class" icon="table">
    Group many files into one logical table by giving them the same `class` value.
  </Card>

  <Card title="Inline references" icon="link">
    Insert a record into another document with `mode=supertag`.
  </Card>

  <Card title="Card layout fields" icon="table">
    Use fields such as `col`, `row`, `cover`, and `warm` to shape the document header and the record cards.
  </Card>
</CardGroup>

## Core Concepts

<AccordionGroup>
  <Accordion title="A record is still a Markdown file" icon="file" defaultOpen>
    A SuperTag record is a normal Markdown document with typed frontmatter.

    ```yaml
    ---
    title:
      type: text
      label: Title
      value: "The Godfather"
    director:
      type: text
      label: Director
      value: "Francis Ford Coppola"
    year:
      type: number
      label: Year
      value: 1972
    class:
      type: text
      label: class
      value: "ClassicMovieEnglish"
    ---
    ```
  </Accordion>

  <Accordion title="The class field groups records" icon="table">
    Files that share the same `class` value belong to the same logical table. `class` must be a text field.

    ```yaml
    class:
      type: text
      label: class
      value: "ClassicMovieEnglish"
    ```

    This is what lets Zditor aggregate many Markdown files into one structured collection. The **Calendar** sidebar lists your classes on its **Objects** tab.
  </Accordion>

  <Accordion title="A schema file defines the fields" icon="list-check">
    A file with the same `class` and a `field` list acts as the class's schema file. `field` names the fields every record should have, and the schema file contains those fields with their types and labels.

    ```yaml
    ---
    class:
      type: text
      label: class
      value: "ClassicMovieEnglish"
    field:
      type: array
      label: field
      value: [title, director, year]
    title:
      type: text
      label: Title
      value: ""
    director:
      type: text
      label: Director
      value: ""
    year:
      type: number
      label: Year
      value: 0
    ---
    ```

    Records you create from the `#` menu start with these fields, copied from the schema file. The schema file also defines the columns of the class's table, and in the knowledge graph every record links to it.
  </Accordion>

  <Accordion title="col and row shape card layout" icon="table">
    Layout fields control which metadata is emphasized in the document header, and on the record cards in the class's **Gallery** view.

    ```yaml
    col:
      type: array
      label: Col
      value: [year, title, director]
    row:
      type: array
      label: Row
      value: [genre, rank, score, watched]
    ```

    - `col` names up to three fields for the title area: a small line above, the title, and a description below
    - `row` names the fields shown in the information row underneath
  </Accordion>
</AccordionGroup>

## Reference Syntax

Use a normal Markdown link with `mode=supertag`:

```markdown
[ClassicMovieEnglish](/movies/The%20Godfather.md|mode=supertag)
```

- The text in brackets is the record's class.
- The path points to the record file. A path starting with `/` starts at the workspace root; any other path starts at the folder of the current document. Spaces in the path are written as `%20`.

In the editor, the reference appears as a colored chip such as `#ClassicMovieEnglish · The Godfather`. The color depends on the class name.

<Note>
  You rarely need to type this syntax. Type `#` in a document to open the object menu, which lists your classes; choose a class, then a record, to insert a reference. **Create Row** creates a new record of the class in the current document's folder, named after the text you enter, and inserts it. **Create Table** starts a new class, which exists once you create its first row. If the menu does not appear, check that **Object menu (#)** is on in **Settings → Editor → Markdown Editor**.
</Note>

Click a reference to select it. The toolbar that appears shows:

- The class name, which opens all records of the class in a tab with **Table**, **Gallery**, and **Gantt** views
- The record name, which opens the record file
- A refresh button, which updates Zditor's index of your notes
- **Info**, which shows the record's fields

## Common Field Types

| Type | In the editor | Typical use |
| --- | --- | --- |
| `text` | Text | title, author, country, notes |
| `number` | Number | year, score, rank |
| `date` | Date | due dates, watch dates, created dates |
| `checkbox` | Toggle | done state, warm theme, featured state |
| `multiselect` | Multi-select | genre, tags, categories |
| `array` | List | cast lists, layout field lists |
| `progress` | Progress | values from 0 to 100, such as scores or completion |
| `asset` | Image | covers and other images |

See the [Frontmatter guide](/en/frontmatter) for every field type and how to edit fields.

## Recommended Workflow

<Steps>
  <Step title="Copy an existing record">
    Start from a file that already has the schema you want, or create the record from the `#` menu with **Create Row**.
  </Step>

  <Step title="Keep the field structure and class">
    Reuse the same keys, types, and `class` value so the record stays in the same collection.
  </Step>

  <Step title="Replace concrete values">
    Update the title, dates, cover, and body content to match the new record.
  </Step>

  <Step title="Backfill new shared fields later">
    If the whole class needs another field, add it consistently across the collection, and to the schema file's `field` list.
  </Step>
</Steps>

<Tip>
  SuperTag works best when field names stay stable over time. Avoid casual renames once a class is already in use.
</Tip>
