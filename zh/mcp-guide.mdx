MCP（Model Context Protocol，模型上下文协议）是把 AI 智能体连接到工具和数据的开放标准。在 Zditor 中添加 MCP 服务器后，智能体就能在每个智能体对话中使用它的工具，与内置工具配合工作。

<Warning>
  只连接你信任的服务器。**Stdio** 服务器是一个以你的访问权限在电脑上运行的程序，而且每个服务器都会收到智能体发给其工具的内容。
</Warning>

## 什么时候需要 MCP

智能体本身已经能处理你的文件、PDF 和画布，运行命令，并操作 Zditor 本身（见 [Agent 智能体使用指南](/zh/agent-guide)）。当任务需要这些之外的能力时，例如问题跟踪系统、数据库、知识库或其他应用的数据，再添加 MCP 服务器。

## 添加服务器

<Steps>
  <Step title="打开 MCP 设置">
    打开 **设置 → AI → MCP 服务器**，点击 **添加服务器**。
  </Step>

  <Step title="为服务器命名">
    填写 **服务器名称**。它在列表、状态更新和工具调用中用来标识这个服务器，必须唯一。名称 `zditor` 已被保留。
  </Step>

  <Step title="选择连接方式">
    在 **传输方式** 中选择 **Stdio**，由 Zditor 在你的电脑上把服务器作为程序启动；或选择 **HTTP** 或 **SSE**，连接到某个网址上的服务器。然后按下表填写该传输方式对应的字段。
  </Step>

  <Step title="测试并保存">
    点击 **测试连接**。连接成功后，Zditor 会报告找到了多少个工具。然后点击 **保存**。
  </Step>
</Steps>

| 字段 | 传输方式 | 填写内容 |
| :--- | :--- | :--- |
| **命令** | Stdio | 启动服务器的程序，例如 `npx` 或某个可执行文件的完整路径。必填。 |
| **参数** | Stdio | 传给该程序的命令行参数。包含空格的值请加上引号。 |
| **环境变量** | Stdio | 为服务器进程设置的名称和值，例如 API 令牌。 |
| **端点 URL** | HTTP、SSE | 服务器完整的 `http://` 或 `https://` 地址。必填。 |
| **请求头** | HTTP、SSE | 每个请求都会附带的名称和值，常见的是带 bearer 令牌的 `Authorization`。 |

<Tip>
  你也可以让智能体替你添加、修改或删除 MCP 服务器。在 **总是询问** 模式下，更改设置需要你的批准。
</Tip>

## 启用和停用服务器

列表中的每个服务器都有一个开关。服务器关闭时显示为 **已停用**，对话不会连接它，也不会加载它的工具。服务器表单的 **状态** 下也有同样的开关。

更改从智能体的下一轮开始生效，已经打开的对话也一样。要修改服务器，点击 **编辑**。**放弃更改** 会丢弃尚未保存的修改；依次点击 **删除** 和 **确认删除** 会移除这个服务器。

## 在对话中使用 MCP 工具

你不需要为每个对话单独选择服务器：每个已启用的服务器在所有智能体对话中都可用。智能体会在任务需要时查找服务器的工具；在请求中点名服务器或工具，可以帮助它做出选择。

- 在 **总是询问** 模式下，每次调用 MCP 工具都需要你批准。读取服务器提供的资源则不需要。
- 服务器在工作时可能会向你索取信息。这时对话中会出现该服务器的表单：填写后点击 **提交**，或点击 **拒绝**。如果服务器请你访问某个网页，**打开并继续** 会打开它。

## 在 iPhone 和 iPad 上

Zditor 无法在 iPhone 和 iPad 上启动程序，所以在这些设备上请使用 **HTTP** 或 **SSE** 服务器。

## 以前内置的 Zditor MCP 服务

<Note>
  早期版本的 Zditor 自带一个内置 MCP 服务，提供 `open_file`、`list_supertag_classes`、`list_agent_sessions` 和 `generate_image` 等工具。它已经不再是 Zditor 的一部分。现在智能体用自己的工具来处理 Zditor 中的事务：它可以读取你的工作区和已打开的标签页、打开文件、切换和关闭标签页、更改设置，并处理 PDF 和画布。SuperTag、会话历史和图像相关的工具没有内置的替代品。旧配置中遗留的名为 `zditor` 的服务器会被自动移除，这个名称也已被保留。
</Note>

## 权限与安全

- 只启用任务需要的服务器，关闭不用的服务器。
- 对于工具能修改内容的服务器，保持 **总是询问** 模式。
- 把令牌和密钥放在 **环境变量** 或 **请求头** 中，不要写进消息里。表单会隐藏这些值，直到你选择显示。
- 服务器设置（包括这些值）保存在本设备上。如果你在 **设置 → 个人 → 同步** 中备份 **连接与密钥**，它们会包含在加密备份中。
- 尽量使用权限范围有限的令牌，并定期更换。

## 常见问题

<AccordionGroup>
  <Accordion title="Stdio 服务器测试连接失败" icon="terminal">
    Zditor 不会显示服务器自身的错误输出，所以请在终端里运行同样的命令，看看哪里出了问题。如果找不到程序，在 **命令** 中填写它的完整路径。从程序坞或访达打开的应用，看到的 `PATH` 可能和终端里的不同：如果服务器还需要其他程序（例如 `npx` 需要 Node.js），添加一个 `PATH` 环境变量，值设为在终端中运行 `echo $PATH` 的输出。
  </Accordion>

  <Accordion title="HTTP 或 SSE 服务器测试连接失败" icon="globe">
    检查 **端点 URL** 和 **请求头**，例如令牌是否已过期。Zditor 会以 HTTP POST 把每个请求发送到端点 URL，并接受 JSON 或事件流形式的回复；只支持旧版 SSE 传输方式（事件流使用单独地址）的服务器可能无法连接。如果服务器提供 Streamable HTTP 地址，请使用它。
  </Accordion>

  <Accordion title="服务器已连接，但智能体不使用它" icon="question">
    检查它的开关是否打开，以及 **测试连接** 能否找到工具。然后在请求中点名这个服务器或工具：智能体只有在判断任务需要时才会查找 MCP 工具。
  </Accordion>

  <Accordion title="添加服务器后回复变慢了" icon="hourglass-half">
    Zditor 会在对话中智能体的第一轮之前、以及你更改服务器列表之后启动每个已启用的服务器，所以一个慢的服务器会拖慢回复。关闭不需要的服务器。
  </Accordion>
</AccordionGroup>
