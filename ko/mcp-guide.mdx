MCP(Model Context Protocol)는 AI 에이전트를 도구 및 데이터와 연결하는 개방형 표준입니다. Zditor에 MCP 서버를 추가하면 에이전트가 모든 에이전트 대화에서 내장 도구와 함께 그 서버의 도구를 사용할 수 있습니다.

<Warning>
  신뢰할 수 있는 서버만 연결하세요. **Stdio** 서버는 사용자의 접근 권한으로 컴퓨터에서 실행되는 프로그램이며, 모든 서버는 에이전트가 그 서버의 도구에 보내는 내용을 받습니다.
</Warning>

## MCP가 필요한 경우

에이전트는 이미 파일, PDF, 캔버스를 다루고, 명령을 실행하며, Zditor 자체를 조작할 수 있습니다([에이전트 가이드](/ko/agent-guide) 참고). 이슈 트래커, 데이터베이스, 지식 베이스, 다른 앱의 데이터처럼 그 이상이 필요한 작업이라면 MCP 서버를 추가하세요.

## 서버 추가

<Steps>
  <Step title="MCP 설정 열기">
    **Settings → AI → MCP Servers**를 열고 **Add server**를 클릭하세요.
  </Step>

  <Step title="서버 이름 지정">
    **Server name**을 입력하세요. 이 이름은 목록, 상태 업데이트, 도구 호출에서 서버를 식별하므로 고유해야 합니다. `zditor`라는 이름은 예약되어 있습니다.
  </Step>

  <Step title="연결 방식 선택">
    **Transport**에서 Zditor가 서버를 컴퓨터의 프로그램으로 실행하게 하려면 **Stdio**를, 웹 주소에 있는 서버에 연결하려면 **HTTP** 또는 **SSE**를 선택하세요. 그런 다음 아래 표에 설명된 해당 전송 방식의 필드를 채우세요.
  </Step>

  <Step title="테스트 후 저장">
    **Test connection**을 클릭하세요. 연결에 성공하면 Zditor가 찾은 도구 수를 알려 줍니다. 그런 다음 **Save**를 클릭하세요.
  </Step>
</Steps>

| 필드 | 전송 방식 | 입력할 내용 |
| :--- | :--- | :--- |
| **Command** | Stdio | 서버를 시작하는 프로그램. `npx` 또는 실행 파일의 전체 경로 등. 필수입니다. |
| **Arguments** | Stdio | 프로그램에 전달할 명령줄 인수. 공백이 들어간 값은 따옴표로 감싸세요. |
| **Environment variables** | Stdio | API 토큰처럼 서버 프로세스에 설정할 이름과 값. |
| **Endpoint URL** | HTTP, SSE | 서버의 전체 `http://` 또는 `https://` 주소. 필수입니다. |
| **Request headers** | HTTP, SSE | 모든 요청에 함께 보낼 이름과 값. 보통 bearer 토큰을 담은 `Authorization`을 씁니다. |

<Tip>
  에이전트에게 MCP 서버를 추가, 변경, 제거해 달라고 요청할 수도 있습니다. **Always ask**(항상 확인) 모드에서는 설정을 바꿀 때 사용자의 승인이 필요합니다.
</Tip>

## 서버 켜기와 끄기

목록의 각 서버에는 스위치가 있습니다. 서버를 끄면 **Disabled**로 표시되며, 대화가 그 서버에 연결하거나 도구를 불러오지 않습니다. 서버 양식의 **Status**에도 같은 스위치가 있습니다.

변경 사항은 이미 열려 있는 대화에서도 에이전트의 다음 턴부터 적용됩니다. 서버를 수정하려면 **Edit**를 클릭하세요. **Discard**는 저장하지 않은 변경 사항을 버리고, **Delete**를 누른 다음 **Confirm delete**를 누르면 서버가 제거됩니다.

## 대화에서 MCP 도구 사용

대화마다 서버를 고를 필요는 없습니다. 켜져 있는 서버는 모든 에이전트 대화에서 쓸 수 있습니다. 에이전트는 작업에 필요할 때 서버의 도구를 찾아보며, 요청에 서버나 도구 이름을 적으면 에이전트가 고르는 데 도움이 됩니다.

- **Always ask** 모드에서는 MCP 도구를 호출할 때마다 승인이 필요합니다. 서버가 제공하는 리소스를 읽을 때는 승인이 필요하지 않습니다.
- 서버가 작업 중에 정보를 요청할 수 있습니다. 그러면 대화에 그 서버가 보낸 양식이 표시됩니다. 양식을 채우고 **Submit**을 클릭하거나 **Decline**을 클릭하세요. 서버가 웹 페이지 방문을 요청하면 **Open and continue**로 페이지를 열 수 있습니다.

## iPhone과 iPad에서

iPhone과 iPad에서는 Zditor가 프로그램을 실행할 수 없으므로 **HTTP** 또는 **SSE** 서버를 사용하세요.

## 이전의 내장 Zditor MCP 서비스

<Note>
  이전 버전의 Zditor에는 `open_file`, `list_supertag_classes`, `list_agent_sessions`, `generate_image` 같은 도구를 제공하는 내장 MCP 서비스가 있었습니다. 이 서비스는 이제 Zditor에 포함되지 않습니다. 대신 에이전트가 Zditor를 다루는 자체 도구를 갖추고 있어 작업 공간과 열린 탭을 읽고, 파일을 열고, 탭을 전환하거나 닫고, 설정을 바꾸고, PDF와 캔버스를 다룰 수 있습니다. SuperTag, 세션 기록, 이미지 도구는 내장된 대체 기능이 없습니다. 이전 설정에서 남은 `zditor`라는 이름의 서버는 자동으로 제거되며, 이 이름은 예약되어 있습니다.
</Note>

## 권한과 안전

- 작업에 필요한 서버만 켜고, 쓰지 않는 서버는 끄세요.
- 도구로 무언가를 변경할 수 있는 서버에는 **Always ask**를 유지하세요.
- 토큰과 키는 메시지가 아니라 **Environment variables** 또는 **Request headers**에 넣으세요. 양식은 직접 표시하기 전까지 값을 가려 둡니다.
- 이 값을 포함한 서버 설정은 이 기기에 저장됩니다. **Settings → Personal → Sync**에서 **Connections and credentials**를 백업하면 암호화된 백업에 포함됩니다.
- 가능하면 범위가 제한된 토큰을 쓰고, 주기적으로 교체하세요.

## 자주 묻는 질문

<AccordionGroup>
  <Accordion title="Stdio 서버에서 Test connection이 실패할 때" icon="terminal">
    Zditor는 서버 자체의 오류 출력을 보여 주지 않으므로, 터미널에서 같은 명령을 실행해 무엇이 잘못되었는지 확인하세요. 프로그램을 찾을 수 없다면 **Command**에 전체 경로를 입력하세요. Dock이나 Finder에서 연 앱은 터미널과 같은 `PATH`를 보지 못할 수 있습니다. 서버에 `npx`용 Node.js 같은 다른 프로그램이 필요하다면, 터미널에서 실행한 `echo $PATH`의 출력값으로 `PATH` 환경 변수를 추가하세요.
  </Accordion>

  <Accordion title="HTTP 또는 SSE 서버에서 Test connection이 실패할 때" icon="globe">
    **Endpoint URL**과 **Request headers**를 확인하세요. 예를 들어 토큰이 만료되었을 수 있습니다. Zditor는 모든 요청을 엔드포인트 URL에 HTTP POST로 보내고 JSON 또는 이벤트 스트림 응답을 받습니다. 따라서 이벤트 스트림용 주소가 따로 있는 예전 SSE 전송 방식만 지원하는 서버는 연결되지 않을 수 있습니다. 서버에 Streamable HTTP 주소가 있다면 그 주소를 사용하세요.
  </Accordion>

  <Accordion title="서버는 연결되었지만 에이전트가 사용하지 않을 때" icon="question">
    서버 스위치가 켜져 있는지, **Test connection**에서 도구가 발견되는지 확인하세요. 그런 다음 요청에 서버나 도구 이름을 적으세요. 에이전트는 작업에 필요하다고 판단할 때 MCP 도구를 찾아봅니다.
  </Accordion>

  <Accordion title="서버를 추가한 뒤 응답이 느려졌을 때" icon="hourglass-half">
    Zditor는 대화에서 에이전트의 첫 턴 전에, 그리고 서버 목록을 바꾼 뒤에 다시, 켜져 있는 모든 서버를 시작합니다. 그래서 느린 서버가 있으면 응답이 늦어집니다. 필요 없는 서버는 끄세요.
  </Accordion>
</AccordionGroup>
