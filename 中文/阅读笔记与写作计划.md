# 从阅读到一篇短文

今天想写清楚一个问题：读过一份资料之后，怎样留下能继续使用的想法？先选一个值得追问的细节，回到原文，把它的意思和自己的理解分别写下来，再决定它能放进文章的哪个位置。

==一条好笔记，既能带我回到原文，也能让我接着往下想。== 摘录负责保留线索，批注记录当时的疑问；写作时，再把这些片段连成自己的判断。

!!! note 本次写作目标
    写一篇关于阅读笔记的短文。用一个具体例子，说明一段摘录怎样经过追问、整理和改写，成为文章里有用的一段话。

## 留下有用的阅读笔记

每次记录，都给 [自己的理解](用自己的话解释这一段为何重要，并保留它在原文中的位置。|mode=tip|style=teal) 留一行空间。暂时不能确定的地方先写成问题，不急着把它变成结论。

这次先读 [注释与修订指南](./Zditor注释与修订指南.md)，把其中的三条提示和自己的理解放在一起：

|资料里的原话 |我的理解 |在文章中的用法 |
|---|---|---|
|给一段文字补充说明，不改原文 |先把问题留在原文旁 |作为阅读场景的例子 |
|给一段文字提出替换建议 |确认理解后，再进入改写 |展示一句话的修改过程 |
|适合标一小段文字 |每次批注只讨论一个问题 |整理成最后的记录建议 |

同一段文字，可以引出不同的理解。把“原文说了什么”和“我由此想到了什么”分开，之后修改观点时，就不容易把自己的推测当成材料里的结论。

## 把线索整理成提纲

先把相近的笔记放在一起，看看它们在回答什么问题。提纲暂定为三个部分：从一个阅读场景开始，展示一条笔记的变化，最后说明下一次可以怎样记录。

```mermaid
flowchart LR
    A[阅读资料] --> B[留下批注]
    B --> C[整理线索]
    C --> D[写出初稿]
    D --> E[回查原文]
```

如果两条笔记的判断相反，先把它们并排保留，找出各自成立的条件。这个分歧可能比两条相似的摘录更适合作为文章的转折。

## 给草稿留一点修改空间

初稿先回答问题，再调整表达。比如，[只要做好笔记，就一定能写出好文章](这句话把记录与写作之间的关系说得过于绝对。|mode=revision|style=indigo|advice=清楚的笔记能为写作提供起点，文章还需要经过取舍、组织和修改)。改写时，把省略的条件补回来，观点才更准确。

回读每一段时，检查它在做什么：交代背景、解释材料，还是提出判断？如果一段话同时承担太多任务，就拆成两段；如果删去之后意思仍然完整，就让它短一点。

> 让读者看见一个想法是怎样形成的，也给他们留下继续思考的余地。

## 下一次写作前

- [x] 确定这篇短文要回答的问题
- [x] 为摘录补上自己的理解
- [ ] 选出一条最有代表性的笔记
- [ ] 按提纲完成初稿，补充具体例子
- [ ] 回查原文，删去没有依据的判断

下次打开这份笔记，先从那个还没回答的问题开始。把新的发现写在旁边，看看今天的理解有没有变化，再决定文章需要怎样修改。
